# 06 · 内网一页纸：照抄就能用

所有命令都在**服务器**上以 root 执行。下面两个变量先设一次，后面整篇都用：

    export DEL=/opt/ST-MCP-DELIVERY-20261026                    # 交付文件夹放哪
    export PKG=$DEL/packages/st-mcp-offline-arm64-20261015   # 已解压的包（按实际路径改）

`PKG` 指向交付夹里已解压的离线包目录。

**单端口**：所有租户共用 `8100` 一个端口、一个容器；每个租户拿到的是
`http://<IP>:8100/mcp/<token>`，加人不重启、不开新端口。

---

## A. 已经部署过的机器：加一个用户（现场用这个）

**不重装、不动主实例、不重启**，只往注册表加一条记录：

    cd /opt
    cp -a /mnt/usb/ST-MCP-DELIVERY-20261026 .            # U 盘挂载点按实际改
    cd "$DEL" && LC_ALL=C sha256sum -c checksums.txt | grep -v ': OK$'
    # 上面应该什么都不打印；有 FAILED 就重拷 U 盘

    sh "$DEL/tools/create-tenant.sh" -t tenant_alice -D "$PKG" -I <db-server-ip>

一条命令做完：建库账号 `TENANT_ALICE` → 往 `$PKG/tenants/tenants.json` 写
token/账号记录 → 打印 URL。不建容器。

判据：最后一行 JSON 里有

    "success": true ... "db_account": "created" ... "service_mode": "new" ...
    "mcp_url": "http://<db-server-ip>:8100/mcp/<token>"

如果是 `service_mode: "old-image"`，说明主容器还是旧镜像：先在包目录
`sh install-all.sh` 重建一次，再重跑本命令。

再验一次能不能查库（URL 用上面打印的）：

    sh "$DEL/tools/curl-mcp-probe.sh" http://127.0.0.1:8100/mcp/<token>
    # 最后一步 execute_sql 返回 "isError":false 即通

放行端口（客户端在别的机器上才需要；只放 8100 一个）：

    firewall-cmd --add-port=8100/tcp --permanent && firewall-cmd --reload

**用户只拿这一段**（口令不用发给用户，token 就是凭据，别发群里）：

    {
      "mcpServers": {
        "st-mcp": { "url": "http://<db-server-ip>:8100/mcp/<token>" }
      }
    }

## B. 不想敲命令：网页开通

    sh "$DEL/tools/start-admin.sh" 8001
    # 浏览器打开 http://127.0.0.1:8001

填租户名 → 点"创建租户" → 页面表格出现该租户，点"复制配置"发用户。
页面上的地址已经带 token；创建、删除、查看都在这一页，原理同 A。

页面默认只监听 127.0.0.1。服务器没有图形界面时，在自己电脑上开隧道：

    ssh -L 8001:127.0.0.1:8001 root@<db-server-ip>

（如果目标机 sshd 写了 `AllowTcpForwarding no`，隧道会握手即断，这是加固项，
改用 `sh "$DEL/tools/start-admin.sh" 8001 --allow-remote` 内网直开即可。）

## C. 全新机器：从零到能查库（约 3–6 分钟）

前置：`uname -m` 是 `aarch64`、`docker info` 正常、`/opt` 有 6 GB 空闲、2003/8100 没被占。

    cd "$DEL/packages"
    LC_ALL=C sha256sum -c st-mcp-offline-arm64-rev10-20261101.tar.gz.sha256

    tar -xzf st-mcp-offline-arm64-rev10-20261101.tar.gz
    export PKG="$DEL/packages/st-mcp-offline-arm64-20261015"
    cd "$PKG"

    cp secrets/st-mcp.env.example secrets/st-mcp.env
    vi secrets/st-mcp.env        # 只改 ST_PASSWORD 这一行（新装库先填厂商默认口令）
    chmod 600 secrets/st-mcp.env

    sh install-all.sh 2>&1 | tee /tmp/install-$(date +%m%d-%H%M).log | tail -40
    # 等到：===== 验收汇总：22 PASS / 0 FAIL / 0 SKIP =====
    # 其中三项是单端口判据：注册表已启用 / 无 token 返回 401 / /healthz 200

    sh set-sysdba-password.sh    # 改掉厂商默认口令，脚本自动同步 secrets 并重启容器

    sh "$DEL/tools/curl-mcp-probe.sh" http://127.0.0.1:8100/mcp/<主账号 token>
    # execute_sql 返回 "isError":false 即通

主账号（`default`）的完整 URL 会在安装结束和 `verify.sh` 里打印，形如
`http://<IP>:8100/mcp/oiqV_...`。要给多人用，接着按 **A** 开租户即可
（`PKG` 已经是新机器上的路径，不用改）。

## D. 日常维护

    sh "$DEL/tools/list-tenants.sh" --base http://127.0.0.1:8100/mcp   # 租户与地址
    sh "$DEL/tools/delete-tenant.sh" -t tenant_alice                  # 删记录，token 立即失效；库账号保留
    docker ps --format '{{.Names}}\t{{.Status}}\t{{.Ports}}' | grep st-mcp
    docker logs --tail 30 st-mcp                                      # 只有一个服务容器

加/删租户不需要重启容器；只有改 `deploy.conf`（端口、库地址、主账号）才需要重跑
`sh install-all.sh`。

改某个租户的库口令（库里先改，再对齐注册表）：

    sh "$DEL/tools/create-db-user.sh" -t tenant_alice --password-stdin

（提示时输入新口令；不要用命令行参数传口令。）

备份只需两样：

    cp -a "$PKG/tenants/tenants.json" /root/tenants-$(date +%F).json   # 600，含明文口令
    cp -a "$PKG/deploy.conf" "$PKG/secrets/st-mcp.env" /root/

## E. 出问题先抓这三样（不要猜）

    docker ps -a --filter name=st-mcp --format '{{.Names}}\t{{.Status}}'
    docker logs --tail 40 st-mcp 2>&1
    sh "$DEL/tools/list-tenants.sh" --base http://127.0.0.1:8100/mcp

对照：

| 看到 | 含义 | 处理 |
|---|---|---|
| 租户 URL 返回 401 | token 错 / 租户被删 / `enabled=false` | `list-tenants.sh` 核对；重新签发 token |
| 不带 token 返回 200 | 服务端还是旧镜像 | 重跑 `sh install-all.sh`，看 `verify.sh` 的 401 项 |
| `db_account` 不是 `created` | 主容器没起 / 主账号没 CREATE USER 权限 | 按 `tenants/sql/<租户>.sql` 手工建号，加 `--no-db-user` 重跑 |
| 租户查库报"无法建立连接" | 库端口没放行或账号口令不一致 | `nc -vz <库IP> 2003`；核对注册表里的账号 |
| 创建成功但用户看不到表 | 该账号名下还没建表 | 用该账号登录后建表；MCP 只能看到本账号 schema |
| `GET /mcp` 返回 406 | 正常：streamable-http 只收 POST | 用 `curl-mcp-probe.sh` 判 |
| 中文系统校验显示「确定」 | 就是 OK | 不用管 |
