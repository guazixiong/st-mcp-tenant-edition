# 05 · 多租户：一个端口、一人一个 token

适用场景：一台机器上跑着神通库，多个用户要各自通过 MCP 访问**自己的数据**，互相看不到。

结论先说：

- **服务端只有一个容器、只占一个端口**（默认 `8100`），一个进程服务所有租户；
- **每个租户 = 一个神通库账号 + 一个 token**，token 决定这次请求用哪个库账号；
- **用户侧只填一个 URL**：`http://<服务器IP>:8100/mcp/<token>`；
- 加/删租户**不用重启**，也不新开端口，服务端按注册表文件的修改时间自动热加载。

隔离靠数据库账号自己的权限，不靠 MCP 层过滤：查询走
`ALL_OBJECTS / ALL_TABLES / ALL_TAB_COLUMNS / ALL_CONSTRAINTS` 这些按"当前账号权限"
过滤的视图，账号只能访问自己的 schema，所以只能看到自己的表。
**建账号时不额外授权别的 schema** 是隔离的唯一前提。

实测（QEMU / 麒麟 ARM64 / 神通 V7.0.8，2026-10-31）：

- 租户 `tenant_demo` 的 `list_schemas` 只返回 `TENANT_DEMO`；
- 主账号建表 `DEMO_SECRET` 后，租户查询返回
  `Relation "DEMO_SECRET" does not exist`，`ALL_TABLES` 计数为 0；
- 错误 token 返回 `HTTP 401`，不带 token 也返回 `HTTP 401`；
- 新增租户后 1 秒内用新 URL 握手 `HTTP 200`（容器未重启）；
- 删除租户后原 token 立即 `HTTP 401`。


## 前置条件

| 项 | 要求 | 怎么确认 |
|---|---|---|
| 主实例已部署 | `verify.sh` 22 PASS | `sh "$PKG/scripts/verify.sh"` |
| 容器认注册表 | `docker exec st-mcp printenv ST_TENANT_REGISTRY` 有输出 | 旧镜像没有这一行，需重跑 `install-all.sh` |
| 注册表在位 | `$PKG/tenants/tenants.json` 存在且 600 | `ls -l "$PKG/tenants/tenants.json"` |
| Docker | 可用（建库账号要复用主容器里的驱动） | `docker info >/dev/null && echo OK` |
| Python | 3.6+（注册表与 token 生成） | `python3 -V` |
| 身份 | root | `id -u` → `0` |

`DEL` 是交付文件夹，`PKG` 是解压出来的包目录：

    export DEL=/opt/ST-MCP-DELIVERY-20261026
    export PKG="$DEL/packages/st-mcp-offline-arm64-20261015"


## 开一个租户（一条命令）

    sh "$DEL/tools/create-tenant.sh" -t tenant_alice -I 10.20.30.10

做的事：

1. 生成库口令（18 位）和 token（24 位 URL 安全字符），只写进 600 注册表，不进命令行；
2. 用主实例容器里的 STPython 驱动、以主容器账号（默认 SYSDBA）执行
   `CREATE USER`；账号已存在则对齐口令；
3. 往 `$PKG/tenants/tenants.json` 追加一条 `token → 库账号` 记录；
4. 打印给用户的 URL 和客户端 JSON。

不建容器、不占端口、不改 `deploy.conf`、不需要重启。建账号失败时会停下，
把 SQL 留在 `$DEL/tenants/sql/<租户>.sql`，不会写一条连不上库的注册表记录。

| 参数 | 含义 | 不填时 |
|---|---|---|
| `-t 租户名` | 必填，字母开头，只能字母数字 `_ -`，最长 28 | — |
| `-u 库用户名` | 指定已有的库账号（迁移旧账号用） | 租户名转大写，`-` 变 `_` |
| `-H 库IP` / `-N 库端口` / `-d 库名` | 连哪台库 | 取 `deploy.conf`，再默认 `127.0.0.1/2003/OSRDB` |
| `-I 对外IP` | 生成 URL 用哪个 IP | 自动探测本机第一块网卡 |
| `-P MCP端口` | URL 里的端口 | 取 `deploy.conf` 的 `HOST_PORT`，默认 8100 |
| `-D 包目录` | 交付包位置 | `ST_MCP_PKG`，或 `$DEL/packages/` 下那一版 |
| `--token` | 指定 token（已有系统对接时才用） | 自动生成；同名租户保留原 token |
| `--restricted` | 该租户禁止写 SQL | 可读写 |
| `--password-stdin` | 从标准输入读库口令（管理界面用） | 自动生成 |
| `--no-db-user` | 不建库账号，只写注册表 | — |
| `--simulate` | 只预览，不建账号、不写注册表 | — |

最后一行是 JSON（管理界面按它渲染）：

    {"success": true, "message": "租户已开通",
     "data": {"tenant": "tenant_alice", "db_user": "TENANT_ALICE",
              "db_account": "created", "access_mode": "unrestricted",
              "mcp_url": "http://10.20.30.10:8100/mcp/<token>",
              "client_config": "{\"mcpServers\": {\"st-mcp-tenant_alice\": {\"url\": \"...\"}}}",
              "service_mode": "new", ...}}

`db_account` 取值：`created`（已建/已对齐）、`manual`（本机没有主容器，需按 SQL 手工建）、
`skipped`、`preview`。`service_mode=old-image` 表示主容器还是旧镜像，注册表已写入但不会生效，
重跑一次 `sh install-all.sh` 即可。

单独补建/对齐库账号（不影响注册表）：

    sh "$DEL/tools/create-db-user.sh" -t tenant_alice


## 验收（三条就够）

    # 1) 租户自己能不能握手（把 URL 换成刚打印的那条）
    sh "$DEL/tools/curl-mcp-probe.sh" http://127.0.0.1:8100/mcp/<token>
    # 最后一步 execute_sql 返回 "isError":false 即通

    # 2) 列表里能看到，且地址带 token
    sh "$DEL/tools/list-tenants.sh" --base http://10.20.30.10:8100/mcp

    # 3) 不带 token 必须被拒
    curl -s -o /dev/null -w '%{http_code}\n' -X POST http://127.0.0.1:8100/mcp \
      -H 'Content-Type: application/json' \
      -H 'Accept: application/json, text/event-stream' \
      -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}'
    # 期望 401

`/healthz` 不需要 token，返回 200，可直接给负载均衡/监控探活。


## 管理界面（不想敲命令就用这个）

    sh "$DEL/tools/start-admin.sh" 8001
    # 浏览器打开 http://127.0.0.1:8001

页面表格列：租户 / 库账号 / 库口令 / 访问模式 / 客户端地址（含 token）/ 操作。
"创建租户"只需填租户名（库地址等默认取 `deploy.conf`）；"复制配置"复制的是
只含 URL 的客户端 JSON；"删除"只删注册表记录，库账号保留。

数据来自 `$PKG/tenants/tenants.json`，页面不含业务逻辑，创建/删除调的是同一批脚本。
界面默认只绑 `127.0.0.1`。要远程访问必须显式加 `--allow-remote`
（页面含明文口令与 token，优先用 `ssh -L 8001:127.0.0.1:8001 root@库机` 隧道；
若目标机 sshd 设了 `AllowTcpForwarding no`，隧道会握手即断，此时只能内网直开
`--host 0.0.0.0 --allow-remote`，并自行限制来源）。


## 用户侧：只填一个 URL

    {
      "mcpServers": {
        "st-mcp": {
          "url": "http://10.20.30.10:8100/mcp/<token>"
        }
      }
    }

用户不需要知道数据库地址、账号、口令。token 就是访问凭据，**不要公开发到群里**；
泄露了就 `create-tenant.sh -t <租户> --token <新token>` 换一个（同名租户默认保留原 token，
所以换 token 必须显式给 `--token`），旧 URL 立即失效。

不方便把 token 放 URL 的客户端，可以改用请求头，地址统一填 `/mcp`：

    Authorization: Bearer <token>
    # 或
    X-ST-Token: <token>

同一个请求里 URL token 与请求头 token 不一致会被 401 拒绝。
`Mcp-Session-Id` 会绑定首次解析出的租户，后续请求可以不带 token；跨租户复用同一个
session id 同样会被 401 拒绝。


## 注册表与回收

`$PKG/tenants/tenants.json`（600，容器内以只读方式挂到 `/data/tenants.json`）：

    {"tenants": [
      {"name": "default", "token": "...", "host": "127.0.0.1", "port": 2003,
       "database": "OSRDB", "user": "SYSDBA", "password": "...",
       "access_mode": "unrestricted", "enabled": true,
       "created_at": "...", "updated_at": "..."}
    ]}

- `default` 是主账号（`deploy.conf` 里的 `ST_USER`），由 `install-all.sh` 维护；
- `enabled: false` 可临时停用某租户，不用删记录；
- 容器里的 `127.0.0.1` 会按 `ST_HOST_GATEWAY`（默认 `172.17.0.1`）改写；
- 直接改这个文件也会生效（服务端按 mtime 热加载），但手改容易写坏 JSON，优先用脚本。

删除：

    sh "$DEL/tools/delete-tenant.sh" -t tenant_alice

从注册表移除记录 → 该 token 下一次请求就 401；同时清掉旧的 `secrets/ instances/ sql/` 残留。
**数据库账号不删**（`DROP USER` 不可逆），需要回收时脚本会把命令打出来，确认后手工执行：

    DROP USER "TENANT_ALICE" CASCADE


## 从旧版（每租户一容器一端口）迁过来

旧版给每个租户起 `st-mcp-<租户>` 容器、占 `8101` 起的端口。新版**不再需要这些容器**，
镜像与服务端也已换成认注册表的版本。迁移步骤：

1. 按 `06-内网部署一页纸.md` C 节重装主实例（会重建 `st-mcp:0.1.0` 并生成 `default` 记录）；
2. 保留原有库账号：对每个旧租户执行一次
   `sh "$DEL/tools/create-tenant.sh" -t <租户> -u <原库用户名> --no-db-user`
   （口令未知时去掉 `--no-db-user` 并加 `--password-stdin`，请输入一致的口令；
   也可以先 `create-tenant.sh ... -u <账号> --no-db-user` 写记录，再用
   `create-db-user.sh -t <租户>` 对齐口令）；
3. 确认新 URL 能查库后，再停掉/删除旧的租户容器（这一步不可逆，逐条确认后再做）：

       docker ps -a --filter name=st-mcp-tenant --format '{{.Names}}'
       docker rm -f st-mcp-tenant_alice        # 逐个确认后执行

旧的 `instances/<租户>.conf`、`secrets/<租户>.env` 可以删除；新版不再读取它们。


## 边界（用之前必须知道）

1. **隔离靠授权，不靠 MCP。** 账号一旦被 DBA 多授了别的 schema，MCP 就看得见。
   建账号/回收权限必须归运维，SYSDBA 口令不留在用户手上。
2. **token 是访问凭据。** 它出现在 URL 里，会进浏览器历史、代理日志、聊天记录。
   按口令级别管理；泄露就换。
3. **注册表里是明文口令。** `tenants.json` 与 `tenants/sql/*.sql` 都是 600；
   备份/打包时不要带上 `tenants/` 目录，也不要贴到工单里。
4. **三类性能工具要实测。** `get_performance_metrics / analyze_db_health / get_top_queries`
   依赖 `v$session` 等动态视图；普通账号有没有权限各家不同。受限账号报权限错属正常，
   按租户决定是否用 `--restricted` 创建。
5. **一个进程服务所有租户。** 单租户的重查询会和其他租户共享 CPU/IO；
   要硬隔离（内存、CPU 配额）仍需按库或按实例拆部署。
6. **升级时必须一起换。** 服务端要认注册表（旧镜像没有这个能力），
   `verify.sh` 里"容器已启用租户注册表 / 无 token 401 / /healthz 200"三项就是判据。


## 排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 租户 URL 返回 401 | token 错、租户被删、`enabled=false` | `list-tenants.sh` 核对；`create-tenant.sh -t <租户> --token <新token>` 重发 |
| 不带 token 返回 200 | 服务端还是旧镜像 | 重跑 `sh install-all.sh`，再 `verify.sh` 看 401 那一项 |
| 租户能连上但 `list_schemas` 为空/报错 | 库账号还没建表，或建在了别的 schema | 用该账号登录确认 `SELECT USER FROM DUAL` 与表 owner 一致 |
| `db_account` 是 `manual` | 本机没有运行中的主容器 | 按 `tenants/sql/<租户>.sql` 手工建号，再 `create-tenant.sh --no-db-user` |
| 报"无法建立连接" | 库地址/端口不通，或容器里的 127.0.0.1 没被改写 | 确认 `ST_HOST_GATEWAY`；`nc -vz <库IP> 2003` |
| 新增租户后仍然 401 | 注册表文件没更新（写到了别的路径），或服务端没挂载 `tenants/` | `docker exec st-mcp printenv ST_TENANT_REGISTRY`；`list-tenants.sh` 看注册表路径 |
| 建表 SQL 报 `DatabaseError` 但表其实已建 | STPython 驱动对 DDL 误抛异常 | 用 `list_objects` 核对，存在即成功 |
